# 外伝IIのお金倍率：解析と実装

戦闘勝利後の原作の配分額を倍率化する方法で、経験値倍率と独立したお金倍率を実装しました。×1／×8／×16／×32／×64／×128／×256を選べます。

## 特定した処理

| 用途 | CPUアドレス |
|---|---|
| 配分人数の退避 | バンク4 6B67〜6B6A：CF73→C8CC |
| 原作の金額抽選 | バンク4 6B78〜6C05 |
| 人数による除算 | バンク4 6C05〜6C13、共通050B |
| 1人分の金額の格納呼出 | バンク4 6C19〜6C1E（ROMオフセット12C19〜12C1E） |
| 金額の作業領域 | CFCF〜CFD2、符号なし32ビット・リトルエンディアン |
| 共通4バイト格納 | 031B〜0326、4バイト目の書込後PC=0323 |
| 倍率化を許可する復帰先 | 6C1F |
| 現在のROMバンク管理値 | CFBD=4 |
| 各メンバーへの加算 | バンク4 6C20〜6C46 |
| キャラクター作業中の所持金 | D02C〜D02F（D013レコード+19h） |
| 登録レコードの所持金 | D095 + 人物番号×128 + 19h |
| 保存処理 | 0D0F→11A3、SRAMレコード先頭A018 |
| 原作の金額表示 | 6C48→021EでCFCFを数値文字列化 |

格納PC・書込先・現在バンク・復帰先・対応命令列をすべて確認して、1人分の金額だけを倍率化します。抽選前の総額や所持残高そのものを倍率化しません。経験値のCFCFへのコピーは別のコピー命令なので介入しません。

対象者の判定は原作に任せます。外伝IIのお金は状態値0だけに配られ、経験値の「状態値3未満」と異なります。配分人数の計算や、この違いを変更しません。

ROMファイルは変更せず、判別にハッシュも使用しません。`RewardSupport` の作品別プロファイルへお金の作業アドレス・呼出元を追加し、既存の設定UI、保存・リセット・ステート復帰を使います。

## 検証

`gold_gaiden2_test` で原作の勝利処理を実行しました。経験値倍率×1／×256の各設定について、お金の全7倍率×全5速度の計70組を確認しています。

- 経験値×1・等速の検証では、通常のお金は1人18。×8で144、×256で4,608（元の所持金100から4,708）。
- 同じ経験値倍率・速度では、お金倍率を変更しても抽選された元の金額が変わらないことを確認。
- 6人分の実加算とSRAMへの反映、未参加の登録人物と所持金以外の全項目の保持を確認。
- 経験値倍率×256との併用、経験値が金倍率の影響を受けないことを確認。
- 状態値1・3への非配分を確認。状態値1は経験値を受け取り、お金は受け取らない原作の条件を維持。
- 上限直前の所持金へ加算し、原作の登録・SRAM保存とも4,294,967,295で停止することを確認。
- 倍率計算自体の上限、別バンク・別復帰先の拒否、設定のステート復帰後の保持も確認。

原作の乱数により元のお金は戦闘や経験値表示の処理時間で変化します。「常に18を得る」機能ではありません。

Androidには `CoreTest.testGaiden2GoldRewards` を追加しました。今回の実機実行は未実施です。宝箱の全分岐、全状態・全人数・全敵種などの網羅検証ではありません。

外伝IIのお金倍率追加後、既存を含むWindows CTest 32件が成功しました。Windows本体・Android本体（arm64-v8a / x86_64）・AndroidテストAPKのビルドも成功しています。
