# 外伝1〜3・GBC版Wizardry1〜3の新規作成ボーナス最大化

Androidは機能メニュー→「サポート」→「作成ボーナス最大」、Windowsは機能メニュー末尾の
同名項目を左右でON／OFFします。Androidでは項目の左半分／右半分をタップしても変更できます。
初期値はOFFです。ONにした後の新規キャラクター作成で、ボーナスを原作上限（外伝1〜3は30、GBC版Wizardry1〜3は60ポイント）にします。
設定は保存され、アプリ再起動・リセット・ROMの開き直し後も維持します。

## 動作

外伝1〜3の生成式は乱数0～3＋7と、2回の判定による各10ポイントの加算で、最大30です。
種族と性格（外伝IIIは性別も）を選んだ後、ボーナスを生成する1回の書き込みだけを30へ変更します。
初回表示の数値変換用RAMにも残ポイントを渡し、表示と実値をそろえます。
能力値の初期値、各能力値の原作上限（外伝I・IIは18）、振り分け、戻し、職業の条件判定と保存は原作の処理を使います。

既存キャラクターや、既に振り分け中のポイントには遡って適用しません。
振り分け途中でON／OFFを変更しても残ポイントは増減しません。適用するには作成をやり直してください。
ステート読込は保存された残ポイントを復元します。使ったポイントを再び30へ補充しません。
設定のON／OFFはステートではなく現在のアプリ設定を使います。

## 対応版と方式

GB版外伝1〜3・GBC版Wizardry1〜3のヘッダーと、各作品の生成処理・表示処理・数値格納処理の命令列を確認します。
他作品や命令列が異なる未確認の版では「対象外」として有効化しません。ハッシュは使用しません。
ROMは変更せず、既存のGambatte書き込みコールバックを使用します。
PC=6E41、アドレスD0FA、保存バンクD0AE=5の組み合わせで生成時だけに適用します。
初回表示は数値変換処理のPC=0310、D0C3への書き込みと復帰先01F8／6FD9を確認して補正します。
OFFでは元の値とCPUの進行をそのまま使います。

## 検証

Windowsの`creation_test`で以下を確認しています。

- 外伝I・IIの全5種族、外伝IIIの全10種族・両性別と、異なる乱数のタイミングで30ポイント。基礎能力値は通常生成と一致。
- 1／1.5／2／3／4倍速での作成。
- 振り分けで30→29、戻しで29→30。全30ポイントを使い切り、原作の能力上限を維持（外伝I・IIは18、IIIは後述）。
- 29ポイント時点のステートを読んでも29のままであること。
- 職業選択・作成確定後、新しいキャラクターへ振り分け結果が保存されること。
- ボーナス生成段階で保存済みキャラクターを変更しないこと。
- OFFの作成結果が元コアの状態と完全一致。命令列が異なる版では拒否。

```powershell
.\build\Release\creation_test.exe .rom/wizardrygaiden1.gb build/bonus/name/core.bin
```

ローカルfixtureは名前を入力して種族選択に入ったステートです。
ROM・セーブ・ステートは配布物に含めません。
CTestへ登録する場合はCMakeの`GBWIZ_CREATION_CHECKPOINT`にパスを指定します。
Androidの`CoreTest.testGaiden1MaxBonus`は同じfixtureをcacheの`gaiden1-create.bin`として使用し、
種族・各速度・リセット後の設定保持・ポイント振り分け・ステート復元・作成確定を検証します。
2026-10-29にWindowsの15テストが成功しました。
Pixel 9aでも作成・報酬倍率・DQ3歩行の回帰検証が成功し、最終版で作成・歩行・メニュー描画・新項目の左右タップの4テストが成功しました。
実機が描画した縦・横画面の画像で新項目が収まることも確認しています。

全職業・全性格の組み合わせや、満員の名簿での操作を網羅するテストではありません。

## 外伝IIの解析と対応（2026-10-31）

外伝IIの原作処理も乱数0〜3＋7、独立した2回の判定で各10を加算する式で、最大30です。酒場や既存人物の編集処理ではなく、訓練場で種族・性格を選び終えた後の新規生成処理を対象にしています。

| 対象 | 外伝I | 外伝II |
|---|---|---|
| 生成処理（物理ROM位置） | 16E1B | 20D57 |
| 生成書込み直後PC／残ポイント | 6E41／D0FA | 4D7D／D009 |
| 保存中ROMバンク | D0AE＝5 | CFBD＝8 |
| 初回表示（バンク内アドレス） | 6FD3 | 4F06 |
| 数値変換／4バイト格納 | 01EF／0308 | 0202／031B |
| 表示用作業RAM | D0C0〜D0C3 | CFCF〜CFD2 |
| 表示補正のスタック復帰先 | 01F8／6FD9 | 020B／4F0C |

外伝IIでは、作成中の種族はD01B、基礎能力値はD021〜D026、登録人物はD095＋登録番号×128バイトです。生成と初回表示だけを作品別プロファイルで照合・補正します。乱数呼出しの回数やCPUの実行時間は変更しません。残ポイントの増減・上限18・職業条件・作成確定・通常セーブは原作に任せます。途中でONにしても残ポイントを30へ補充しません。

Windowsの共通creation_testで、外伝I・IIとも全5種族×全5速度、乱数タイミングの変更、基礎能力の非変更、割当と払戻し、ステートで使ったポイントを維持、30ポイントの使い切り、上限18、職業選択・作成確定後の登録データとSRAMへの一致、OFF時の原作コア状態との完全一致を確認しました。

外伝IIのローカルfixtureは名前を入力済みの種族選択画面です。CTestではGBWIZ_GAIDEN2_CREATION_CHECKPOINTで指定します。AndroidのCoreTest.testGaiden2MaxBonusも全種族・全速度、割当・払戻し・作成確定、リセット後の設定保持を同じ画面から検証します。ROM・ステートはアプリや配布物へ同梱しません。

最終確認：Windowsの関連7テストが成功し、ボーナス表示30も実画面で確認しました。Pixel 9aでは外伝I・IIの全5種族×全5速度（計50条件）と割当・作成確定を検証する2テストが成功しました。Windows Release／Android Debugをビルドし、Android開発版を実機へ更新済みです。既存のリリース準備版rc4は上書きしていません。

## 外伝IIIの解析と対応（2026-10-31）

外伝IIIも最大値は30ポイントです。ROMバンク8の51CA（物理位置211CA）が乱数0〜3＋7と、独立した2回の各10加算を計算し、CB14へ保存します。書込み直後のPC=51F0と保存中ROMバンクCAC7=8を照合して、生成時の残ポイントだけを30へ変更します。

初回表示は5402から数値変換0185、共通4バイト格納029Eへ進みます。CAD9〜CADCの最後の書込みPC=02A6で、スタック復帰先018E／5408を確認して表示用の値も30に合わせます。振り分けや払戻しで再表示する場合は、残ポイントをそのまま使用します。

外伝IIIは性別2種類・種族10種類です。作成中の性別CB88、種族CB27、基礎能力値CB2D〜CB32、登録人物CBA1＋登録番号×128バイトを確認しました。能力値は原作の種族基礎値＋10が上限で、男性の力・女性の生命力には生成時点で＋1補正があるため、追加で割り振れるのは該当能力で9、その他で10ポイントです。外伝I・IIの上限18へ置き換えず、割当・払戻し・職業判定・登録・通常セーブをすべて原作で処理します。

Windowsのcreation_testは外伝IIIの両性別・全10種族・全5速度に対応しました。異なる乱数タイミング、種族／性別による初期能力の維持、30ポイントの割当、払戻し、性別補正を含む能力上限、登録後の能力値とSRAMの一致、OFF時の原作コア状態との完全一致を検証しています。外伝I・IIの既存作成検証も成功しています。

ローカルfixtureは名前を入力済みの性別選択画面で、CTestのGBWIZ_GAIDEN3_CREATION_CHECKPOINTで指定します。AndroidのCoreTest.testGaiden3MaxBonusも両性別×全10種族×全5速度と、振り分け・払戻し・作成確定・リセット後の設定保持を検証します。ROM・ステートは配布物へ含めません。

外伝IIIはSRAMバンク3の一部をメニュー用作業領域にも使います。生成前後の「登録済み人物の非変更」は、人物・バックアップ・検証値を持つバンク0で確認します。原作の作業領域への書込みは妨げません。ON／OFFで同じ作成操作をした場合の全SRAM一致もWindows側で確認しています。

最終確認：外伝I〜IIIの作成検証3件と関連する倍速・ステート・対応判定5件が成功しました。Pixel 9aでは外伝IIIの両性別×全10種族×全5速度（100条件）、割当・払戻し・作成確定・リセット後の設定保持を含む実機テストが成功しました。Android開発版を更新済みです。リリース準備版rc4は以前の候補として保持しています。

## GBC版Wizardry1〜3（2026-10-31）

GBC版の原作上限は外伝の30とは異なり、60ポイントです。乱数0〜4＋5から始め、乱数0〜19が15の間は10を加算して再判定し、60以上になったとき60へ制限します。種族は5種類で、割当後の能力値上限は各種族の基礎値＋10。6能力へ各10ポイントを配ると、60ポイントをすべて使い切れます。

| 作品 | 抽選処理（バンク6） | 抽選後の残ポイント保存 | 能力値加算・上限判定 |
|---|---|---|---|
| Wizardry1 | 5B0B〜5B35 | 532A〜532C（直後PC=532D） | 54A0〜54D0 |
| Wizardry2 | 5B9C〜5BC6 | 537C〜537E（直後PC=537F） | 54F2〜5522 |
| Wizardry3 | 5B02〜5B2C | 5321〜5323（直後PC=5324） | 5497〜54C7 |

残ポイントは固定WRAMのC00C、基礎能力値はC006〜C00B、編集中の能力値はC9AD〜C9B2です。ON時は、抽選を最後まで実行した後の、作成処理によるC00Cへの保存だけを60へ変更します。ROMバンクC049=6とWRAMバンク1、呼出PCと書込先を照合します。ヘッダー・抽選・抽選結果の保存・能力上限の命令列を検証し、他作品や未確認の処理へ適用しません。ROMファイル・実行中ROMは書き換えず、ハッシュによる判別も行いません。

表示と割当はその後の原作処理がC00Cを読みます。初期能力や乱数消費・CPU時間、残ポイントの増減、基礎値＋10の上限、職業条件、登録、通常セーブは原作を使用します。途中のON／OFFやステート読込で残ポイントを60へ補充しません。

Windowsのcreation_color_testは各作品の全5種族×全5速度で、60ポイント、種族基礎値の維持、割当・払戻し、途中のON／OFF、ステート復帰、6能力すべての原作上限、60ポイントの使い切り、人物登録と110バイトの登録レコード／SRAM一致を確認します。OFFでは原作コア状態との完全一致、抽選・保存・能力上限の命令列を変えた版の拒否も検証します。

ローカルの種族選択ステートは、町の状態のコピーから通常のキー入力で「まちはずれ→訓練場→キャラクター作成」へ入り、名前を入力・確認したものです。画面の初期化も原作で行い、WRAMバンク1を使用します。ROM・ステートは製品コードや配布物へ含みません。AndroidのCoreTest.testWizardryColorMaxBonusも全3作品×全5種族×全5速度（75条件）、割当・払戻し・作成確定・通常セーブと、リセット後の設定保持を検証します。
