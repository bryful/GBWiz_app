# GBWiz 開発項目と着手順（検討案）

AGENTS.mdと既存の実装・検証記録をもとに、開発する順序を整理します。日付・期間は設定せず、各段階の完了条件で次へ進みます。実装済みの記載は既存資料に基づき、この計画作成時にテストを再実行したものではありません。

## 推奨する進め方

作品単位で遊べる状態を仕上げてから次の作品へ進みます。まず最優先の外伝1を完成させ、そこで確認した仕組みを外伝2以降へ展開します。全作品へ同じ機能を先に広げる方式よりも、外伝1を実際に使いながら改善しやすく、作品固有の差も確認できます。

Windowsで共通処理を実装・検証し、各機能をAndroidでも確認します。Androidの検証は最後にまとめず、各段階の完了条件に含めます。

## 1. 既存機能と保存の動作確認

新機能を積む前に、外伝1を安心して遊べる基準状態を確認します。

- 通常セーブ、5スロット、ROM切替、リセット、バックグラウンド復帰。
- 既存の報酬倍率・作成ボーナス・全呪文習得・全体設定のMP消費なし。
- 最新のキャラクター選択・編集経路をAndroid実機で確認。
- 倍速時の主要場面の音声とキーリピート。

完了条件：保存・復帰と既存サポートの動作を確認でき、新機能で比較する検証用データがそろうこと。実機が使えない場合は自動テストまで進め、実機確認は残件として管理します。

## 2. 外伝1のキャラクター属性変更

実装・検証済み。[操作と検証結果](alignment-support.md)を参照してください。既存のキャラクター選択・保存処理を再利用して、善・中立・悪への変更を追加しました。Windows全19テスト、Android実機8テストが成功しています。

完了条件：選択対象だけが変わり、ゲーム操作を続けた後・通常セーブから再起動した後にも維持されること。他のキャラクター項目を変更しないこと。

## 3. 外伝1のMP消費サポート

実装・検証済み。実装しやすい消費ゼロ方式を採用し、[MP消費なし](mp-support.md)をキャラクター選択不要の全体設定ON／OFFとして追加しました。方式選択やキャラクター別のON／OFFは設けません。従来の個別MP回復は操作画面から外しています。現在MPが0の場合の使用制限は原作どおりです。

完了条件：全体設定のONが各パーティーメンバーに適用され、メンバー交代後も有効であること。ON中の呪文使用、OFFに戻した後の通常消費、倍速・リセット・ステート読込との組み合わせを確認できること。

## 4. 外伝1の善悪混合パーティー

実装・検証済み。[善悪混合パーティー](party-support.md)を全体設定のON／OFFとして追加しました。キャラクターの属性・他の項目・6人上限は維持します。OFFに戻しても既存パーティーを強制解散せず、次の追加に原作の相性判定を適用します。Windowsの既存20件と新しい混合検証、Android実機10件が成功しています。

完了条件：ONで混合編成でき、OFFで通常の編成判定に戻ること。編成後の保存・復帰を確認し、OFFへ戻したときの既存パーティーの扱いも明記すること。

## 5. 外伝1の仕上げとマロールの可否判断

- 報酬倍率、作成ボーナス最大、MP、全呪文、属性、混合、ロゴスキップを通して確認。
- マロールの場所・シナリオ制限を調査。適用条件と移動先の整合性を確認できれば実装し、困難ならAGENTS.mdに従って見送り。
- マロールの初期調査では全面解除は高コストと判断し、[調査結果と選択肢](malor-investigation.md)を記録。その後のユーザー指示に従い、追加解析・実装は保留。
- サポートメニューの項目増加に合わせ、Android縦横画面の操作性を確認。

完了条件：外伝1の必須項目が利用でき、マロールの対応可否と既知の制限が記録されていること。任意のマロール調査が他作品への着手を止め続けないようにします。

## 6. 外伝2へ展開

作品固有の命令列・キャラクター構造・保存形式を確認して、次の順で進めます。

1. 経験値・お金倍率。
2. 新規作成ボーナス最大。
3. キャラクター選択・全呪文習得・属性変更。
4. MP9固定または消費ゼロの実装しやすい一方を、全体設定のON／OFFとして追加。
5. 善悪混合、ロゴスキップ。
6. マロールの可否判断と作品全体の検証。

報酬・作成で普段のプレイを快適にし、キャラクター選択と保存の基盤を確認してから個別操作を追加します。外伝1と共通化するのは確認できた部分だけにします。

## 7. 外伝3へ展開

外伝2と同じ順序で進めます。呪文体系・職業などの作品固有の差を先に調べ、全呪文習得やMPの対象範囲を決めます。

## 8. GBC版Wizardry 1 → 2 → 3へ展開

1作品ずつ、外伝2と同じ項目順で仕上げます。GB版のアドレス・保存構造は流用せず、GBC版の処理を確認します。Wizardry 1で共通化できる構造を見極め、2・3でも作品ごとに照合します。

各作品の完了条件：全体サポートのON／OFF、個別編集の対象選択、通常セーブ・ステート・倍速併用をWindows／Androidで確認し、マロールの対応可否を記録すること。WizardryのMPサポートは各作品で実装しやすい一方を採用し、全体設定とします。

## 9. DQ3のサポート

1. 経験値・お金倍率（必須）。
2. MP消費ゼロの全体設定ON／OFF（容易なら実装）。
3. キャラクターの性格変更（容易なら実装）。
4. 性格診断スキップと指定性格への設定（容易なら実装）。
5. 新規キャラクター作成時の全職業選択（容易なら実装）。

常用する報酬とMPを先に進めます。性格データの変更・保存を確認してから、開始イベントのスキップを調べる順序です。任意項目は困難なら見送り、既存の歩行・戦闘・等速音声が維持されることを確認します。DQ1&2は開発対象から除外します。

## 横断して進める項目

| 項目 | 着手するタイミング | 確認内容 |
|---|---|---|
| AndroidのROM初期場所 | 基本操作・保存の確認時 | 現状Documents/GBWiz/romと指定Documents/NesDQの差を解消。既存フォルダ選択とセーブを維持 |
| Xbox／Pro実機 | 接続できる段階から | NES配列、AB交換、メニュー、LT保存、右スティック読込 |
| 倍速・等速音声 | 各作品の仕上げ時 | 1.5／2／3／4倍、主要BGM・SE、キーリピート。DQ3の細かな音程差は既存記録に従い低優先 |
| Android UI | サポート項目追加ごと | 縦横表示、タップ、項目の左右変更、対象選択 |
| 共通化 | 外伝2への展開時以降 | 実際に共通する処理だけを抽出。作品別の適用条件を保持 |
| 配布準備 | 対象作品の対応と実機検証後 | GBWiz_appの配置スクリプト、同梱物、署名手順を整理 |

署名鍵はAGENTS.mdでGBWiz_signingが指定されていますが、現在の作業許可先はWiiz_signingです。署名作業に入る段階で配置先を確認します。

## 共通の判断基準

- ROM判別にハッシュを使わず、ヘッダー・必要な命令列等を確認。未確認版ではゲーム固有サポートを有効化しない。
- 保存名はROM名。WindowsはAppData/Roaming、Androidの設定・セーブ・ステートはDocuments/GBWiz配下。
- 報酬は経験値とお金を独立に×1／×8／×16／×32／×64／×128／×256で確認。倍率が困難なら許可された単純加算を検討し、桁あふれ・二重加算を防ぐ。
- キャラクター編集は対象以外を保持し、保存の検証値・複製も整合させる。
- 速度変更は左右操作。既存のコントローラー割当と5スロットを維持する。
- 各機能の完了は実装だけでなく、通常動作・保存復帰・Android確認まで含める。
- マロールとDQ3の任意機能は、実現性を判断してから追加する。必須項目の未完了は残件として明示する。

開発側に外伝2・3の善悪混合、外伝2のMP消費なし、Wiz1〜3のロゴスキップを追加しました。Windows全27テスト・Android実機8テストが成功しています。その他のサポートは[展開状況とコスト判断](porting-status.md)のとおり保留し、DQ3の機能は現状維持とします。
