# GBC版Wizardry I：経験値倍率の解析と実装

戦闘終了時に原作が人数で分配した1人分の経験値へ、×1／×8／×16／×32／×64／×128／×256を掛けます。加算対象・表示・キャラクターへの加算・通常セーブは原作に任せます。

| 用途 | CPUアドレス・形式 |
|---|---|
| 経験値配分の呼出 | ROMバンク1 6593: CALL 6C97、復帰先6596 |
| 戦闘の経験値総額 | WRAMバンク1 D47E〜D483 |
| 人数算出・除算 | 6CBB: CALL 28FE、6CBE: CALL 0E91 |
| 分配後の1人分 | HRAM FFB8〜FFBD、6バイトのビッグエンディアンpacked BCD |
| 倍率化のタイミング | 最終バイトFFBDへの書込後PC=6CE5（書込命令は6CE2） |
| 現在バンクの検査 | C049=1、FF70の下位3ビット=1 |
| キャラクターレコード | 固定WRAM C10A + 人物番号×6Eh（110バイト） |
| 経験値 | レコード+17h〜1Ch、6バイトBCD |
| 状態判定・加算 | 6CF3で状態値4以上を除外、6D1Dで共通BCD加算0DDBを呼出 |
| 通常セーブ | SRAMバンク0 A02B + 人物番号×6Eh。加算後レコードと一致を検査 |

外伝の4バイト符号なし整数とは形式が異なるため、GBC版I専用のBCD処理を追加しました。12桁の上限999,999,999,999で配分額を止め、原作のBCD加算も同じ上限で飽和します。BCDの各桁を検査し、不正な値には介入しません。

ROMヘッダーの作品名と、分配・加算・呼出元の命令列を照合します。ハッシュやROMの書換は使用しません。実行中もPC・書込先・ROM/WRAMバンク・スタック復帰先をすべて確認し、経験値の作業領域だけを変更します。お金倍率は後続の[解析と実装](wizardry1-gold-analysis.md)で対応しました。

## 検証方法

コピーした既存の迷宮ステートから、原作の遭遇入口5DB2へ入り、D139=1で通常の戦闘を開始しました。ROMは改変せず、戦闘と勝利を原作処理で進め、経験値配分の直前フレームをローカルfixtureとして保存しました。人物の経験値や勝利結果を直接作る方法ではありません。

この戦闘の1人分は156。×8で1,248、×256で39,936が6人それぞれに加算されます。通常セーブの各レコードでも同じ増分を確認します。

`reward_wizardry1_test` は全7倍率×全5速度（1／1.5／2／3／4倍速）を検査します。×1・等速の原作コア状態との完全一致、SRAM反映、経験値・お金以外の人物データ保持、状態値4の除外、原作加算と倍率計算それぞれの12桁上限、バンク・復帰先・BCDの拒否、ステート復帰後の倍率保持も検査します。お金の原作乱数は表示や経過時間によって変化し得ます。

```powershell
cmake -S . -B build -DGBWIZ_WIZARDRY1_REWARD_CHECKPOINT="C:/path/to/before-experience.bin"
ctest --test-dir build -C Release -R rewards_wizardry1 --output-on-failure
```

Androidにも `CoreTest.testWizardry1ExperienceRewards` を追加しました。ローカルfixtureはアプリcache内の `test.gbc` と `wizardry1-before-experience.bin`。全倍率のSRAM反映とリセット後の設定保持を検査します。今回のAndroid実機実行は未実施です。

ROM・セーブ・検証用ステートは配布物に含めません。全敵・全人数・全状態異常の組合せを網羅した検証ではありません。

検証結果：既存を含むWindows CTest全34件成功。Windows Release、Android Debug（arm64-v8a／x86_64）、AndroidテストAPKのビルドが成功しました。今回のAndroid実機操作は未実施です。
