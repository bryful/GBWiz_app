# GBC版Wizardry II・III：全呪文習得・現在MP／最大MP9

Iと同じキャラクターサポートから対象の登録番号を選び、「全呪文習得」を実行します。魔術師系25・僧侶系29の全54呪文を習得し、両系統の全7段階の現在MP・最大MPを9にします。通常セーブにも保存します。

町の施設選択・酒場・宿屋などの施設内・迷宮・キャンプで使用できます。場所の制限はありません。戦闘中と人物データ転送中の保護は維持します。キャラクター名と登録番号で選択できます。I〜IIIで共通の文字選択表を照合し、ひらがな・カタカナ・英数字・記号をUnicodeへ復号します。属性変更は外伝1のみです。

## 解析と実装

ROMヘッダーと作品別の命令列を照合し、ハッシュや製品ROMの書換は使用しません。以下を手元の各作品のROMで照合しました。物理ROMオフセットで記した箇所は、CPUのバンク切替窓とは区別しています。

| 用途 | II | III |
|---|---|---|
| 人物レコード取得（CPU） | 276E | 273C |
| 習得段階のフラグ取得（物理ROM） | F143 | F143 |
| 段階別呪文開始番号（物理ROM） | A979 | A988 |
| 現在MP／最大MP表示（物理ROM） | F5BF | F5BF |
| 通常セーブ人物転送（CPU） | 2BFE | 2BC9 |
| セーブ検証値計算（CPU） | 2B2B | 2AF6 |
| 原作の通常セーブ読込（CPU） | 2C37 | 2C02 |
| 戦闘モード3設定（CPU） | 19F3 | 19C1 |

3作品とも登録人物はC10Aから110バイト×20人、通常セーブの人物はSRAMバンク0のA02Bからです。作業用人物はC9A2から110バイトです。

MPは人物レコード+26h〜33hの14バイト。現在値が上位4ビット、最大値が下位4ビットなので、全バイトを99hにします。習得フラグは+34h〜41hの14バイトで、段階別開始番号は両作品とも `0,4,7,11,14,18,22,25,30,34,38,43,47,51,54`。Iと同じ習得マスクを使用し、未使用の上位ビットは保持します。

通常セーブはA000〜ABFDの8ビット加算値とその反転をABFE・ABFFへ保存します。対象人物の呪文・MPのみをWRAMと通常セーブへ反映し、人物作業領域に対象人物が読込済みの場合は同じ領域だけを同期します。作業領域の対象は転送元を追跡し、ステート復帰後はレコード全体を照合します。

施設で使う110バイト転送は作品ごとに次の9か所を検証しています。共通コピー0D49・クリア07D6に加え、これらの途中や割込で中断された転送も判定します。

| 作品 | 物理ROMオフセット（転送ループ直前のB=6Eh設定） |
|---|---|
| II | 194B6, 199A3, 1B4EA, 1B65E, 1BD80, 1C8FB, 1CF29, 2267B, 227C3 |
| III | 1945B, 19909, 1B194, 1B308, 1BA2A, 1C8EC, 1CF1A, 22693, 227DB |

[Iの詳細](wizardry1-spells-analysis.md)と共通の編集処理を使用し、プロファイルでアドレス差を扱います。外伝1の既存処理は維持しています。

## 検証方法

`spell_wizardry1_test` を3作品共通のテストに拡張しました。各作品の既存登録人物を対象に、未習得・使用途中MPからの全54呪文習得と現在／最大MP9、他人物・他能力値・未使用ビットの保持、繰返し適用の同一性を検査します。保存したSRAMを別コアへ渡し、各作品の原作読込ルーチンで検証値が受理され、人物レコードが一致して復元されることも確認します。

町・酒場・酒場の人物選択・宿屋の人物選択・宿屋の部屋選択は、原作の操作入力から作成したローカルステートを使います。施設作業領域の同期、未保存HPの保持、別人物への非干渉、戦闘・空人物・不正番号・異なる保存人物・未確認ROM・各作品9か所の中断転送の拒否も検査します。

ROM・セーブ・ステートは配布物へ含めません。Android実機での操作検証は未実施です。

検証結果：GBC版I〜IIIの18ケースと外伝1の回帰3ケース、計21テストがすべて成功しました。Windows Release、Android Debug（arm64-v8a／x86_64）のビルドも成功しました。
