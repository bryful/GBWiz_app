# 外伝II 戦闘終了時の経験値倍率の解析

## 結論

外伝Iと同じ方式で実装できます。人数で分配した後の1人分の経験値を作業RAMで倍率化し、表示・対象者判定・加算・保存は原作の処理に任せる方法です。

調査用プローブで実際の戦闘を終了させ、×1 / ×8 / ×16 / ×32 / ×64 / ×128 / ×256の実加算と通常セーブRAMへの反映を確認しました。解析後、アプリにも経験値倍率を実装しました。最新の操作・対応状況・追加検証は[戦闘報酬サポート](reward-support.md)を参照してください。以下は初期解析時の記録です。

## 特定した場所

CPUアドレスを記載します。バンク4はROMファイル内の8000hを加えた位置です。

| 用途 | 外伝II | 外伝Iの対応箇所 |
|---|---|---|
| 経験値配分額の格納呼出 | バンク4 6AF6〜6AFB | バンク4 6AA9〜6AAE |
| 共通4バイト格納 | 031B〜0326 | 0308〜0313 |
| 最終バイトの書込後PC | 0323 | 0310 |
| スタック上の復帰先 | 6AFC | 6AAF |
| 1人分の経験値 | CF74〜CF77 | D068〜D06B |
| 表示用のコピー先 | CFCF〜CFD2 | D0C0〜D0C3 |
| 現在のROMバンク管理値 | CFBD = 4 | D0AE = 4 |
| キャラクター作業レコード | D013〜D092 | D104〜D183 |
| 経験値の作業フィールド | D040〜D043（レコード+2Dh） | D131〜D134 |
| 登録レコード先頭 | D095、128バイト×20人 | D186、128バイト×20人 |
| 通常セーブRAMの登録先頭 | A018（SRAMオフセット18h） | A017 |

数値は4バイトのリトルエンディアン、符号なし32ビットです。BCDではありません。

## 原作の処理経路

1. バンク4 69C2〜69F4で配分対象人数をCF73へ集計します。D01E（状態フィールド）の値が3未満のメンバーを数えます。
2. 6A96〜6ADDで敵グループの経験値CF5F〜CF60と倒した数を使い、CF74へ集計します。
3. 6ADF〜6AE7で原作の10倍換算を行います（049Fは32ビットの乗算）。
4. 6AE8〜6AF5で対象人数を渡し、037Cの32ビット除算で1人分を求めます。
5. 6AF6〜6AFBから031Bを呼び、結果をCF74〜CF77へ格納します。ここが倍率を掛ける候補です。
6. 6AFC〜6B05で表示用にコピーし、原作のメッセージを表示します。
7. 6B2C〜6B5Dでパーティーを巡回し、状態が3未満のキャラクターについてCF74の配分額をD040の経験値へ加算します。
8. 11A3の原作保存処理で登録レコード・SRAMへ反映します。

総額を先に倍率化してから人数で割る方式とは、割り算の切り捨て分だけ異なる可能性があります。外伝Iと同じ「原作の1人分×倍率」に揃えるのが自然です。

## 介入条件

既存のGambatte書込コールバックで、次をすべて満たす場合だけ処理します。

- 対応ROMタイトルと、格納・経験値配分の命令列が一致
- PC = 0323
- 書込先 = CF77（4バイト目）
- CFBD = 4
- 有効なWRAM上のSPが指す復帰先 = 6AFC

先に格納されたCF74〜CF76と今回の書込値から32ビット値を復元し、64ビットで倍率を掛け、FFFFFFFFhを上限として4バイトを書きます。元の4バイト目の書込を抑止し、命令数・CPU時間は変えません。

031Bは多数の処理で共用されます。PCやRAMアドレスだけの判定では不十分です。バンクと復帰先も必ず確認します。ROMファイルは変更せず、ROM判別にハッシュは使いません。

## 実行検証

既存の外伝II戦闘ステート（クリーピングバイン5体、6人パーティー）を、調査用プローブで実際に終了させました。通常の配分額は1人125でした。

| 倍率 | 各キャラクターへの加算 |
|---|---:|
| ×1 | 125 |
| ×8 | 1,000 |
| ×16 | 2,000 |
| ×32 | 4,000 |
| ×64 | 8,000 |
| ×128 | 16,000 |
| ×256 | 32,000 |

- 各倍率とも介入箇所の通過は1回。6人全員への実加算を確認。
- 生の登録レコードとSRAMの経験値が一致。
- ×1を基準に20人分の全128バイトを比較し、経験値・所持金以外のキャラクターフィールドに差がないことを確認。
- 所持金は倍率化していませんが、経験値表示の桁数・処理時間で後続の乱数が変わり、原作のお金の抽選結果が変化しました（この検証では1人16〜22）。既存の外伝Iと同じ注意点です。
- 上限直前の経験値4,294,967,285に×8の報酬1,000を加える調査用状態を作り、原作加算が4,294,967,295で止まり、桁あふれしないことを確認。

全状態異常・人数・敵種・逃走終了・複数戦闘・全速度の組合せ、アプリUIとAndroid実機は今回の検証対象外です。配分人数と資格判定は静的に特定していますが、状態異常ごとの動作をすべて実プレイした結果ではありません。

## 再現用ツール

`tools/gaiden2_reward_probe.cpp` は独立した解析用実行ファイルです。アプリのRewardSupportには変更を加えていません。

```powershell
# 既存の戦闘ステートから通常の勝利を再現し、経験値配分直前のステートを採取
.\build\Release\gaiden2_reward_probe.exe .rom/wizardrygaiden2.gb build/gaiden2/encounter/core.bin build/gaiden2-reward-analysis/base

# その直前から×256の加算を追跡
.\build\Release\gaiden2_reward_probe.exe .rom/wizardrygaiden2.gb build/gaiden2-reward-analysis/base/before-experience.bin build/gaiden2-reward-analysis/x256 256
```

`before-experience.bin`、`after.bin`、`wram.bin`、`battery.bin` と描画バッファを検証用build配下へ出力します。ROM・セーブ・ステートは配布物に含めません。

## アプリ対応時の変更範囲

既存のRewardSupportを作品別プロファイルにし、上記の外伝II用アドレスを追加する形で共通化できます。倍率の設定・左右操作・音声コールバックは既存の仕組みを使えます。

既存APIは経験値とお金の対応可否が共通なので、経験値だけ先に追加する場合は、未検証のお金倍率を選べないよう対応可否の分離も必要です。外伝IIのお金の格納候補はバンク4 6C19〜6C1Eですが、今回は経験値のみを検証しました。
