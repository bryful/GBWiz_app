# GBC版Wizardry I〜IIIのキャラクター名

キャラクター選択一覧・選択後の見出し・操作結果に、登録番号と実際の名前を表示します。名前が同じ人物も登録番号で区別できます。WindowsとAndroidは共通の復号処理を使用します。

## 名前の形式

人物レコードの先頭10バイトは、登録状態1バイト、名前の文字数1バイト、名前8バイトです。名前は文字数を上限8文字へ制限して読みます。文字コード01hは小さい「ぇ」なので、ゼロ終端文字列やASCIIとしては扱いません。

文字は原作のひらがな・カタカナ・英大文字・英小文字の4つの入力ページに従います。濁点・半濁点は原作が濁音・半濁音の文字コードへ変換して保存します。独立して保存された濁点・半濁点も表示します。英数字と入力可能な記号にも対応します。未定義コードは置換文字「�」で表示し、名前以外の領域を読みません。

| 作品 | 原作の名前描画処理 | 文字入力ページの開始（物理ROM） |
|---|---|---|
| I | ROMバンク3 52A7、+1の文字数を取得して+2から描画 | 20D5C、20F92、211C8、213FB |
| II | Iと同じ名前形式 | 20DD2、21008、2123E、21471 |
| III | Iと同じ名前形式 | 20DEA、21020、21256、21489 |

4ページの内容は3作品で一致します。各ページ67項目を原作ROMと照合しています。濁点変換表は3作品とも物理ROM C9ACにあり、かな・カナの濁音・半濁音と「ヴ」を確認しました。名前文字コードの例は15h=せ、AAh=ん、11h=し、31h=1です。

製品ROM・人物データ・通常セーブの書換は行わず、表示時だけUnicodeへ復号します。ROMのハッシュは使用しません。

## 検証

`wizardry_name_test` は3作品それぞれの原作文字選択表268項目と復号結果を照合し、濁音・半濁音・小さいかな、8文字の混在名、空名、末尾の未使用データ、破損した長さ、未定義コードも検査します。

既存の `spell_wizardry1_test` でも3作品の登録人物名「せんし1」「せんし2」「まほうつかい1」を確認し、同名人物が別の登録番号で一覧に残ることを検査します。

検証結果：3作品の文字表・登録人物名・同名人物の区別と、既存の人物編集・通常セーブ検証を含む21テストが成功しました。Windows Releaseのビルドも成功しました。
