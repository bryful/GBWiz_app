# 外伝2・3：全呪文習得と現在MP・最大MP9

機能メニュー→サポート→キャラクターを選択→全呪文習得から実行します。Windowsではキャラクターサポートから操作します。対象は登録済み人物で、町・施設・迷宮・キャンプなど場所の制限はありません。戦闘中・人物データ転送中と、作業用人物の対応が曖昧な場合のみ拒否します。

- 外伝2：魔術師系31・僧侶系32の計63呪文、14段階の現在／最大MP9。
- 外伝3：魔術師系30・僧侶系32・錬金術師系27の計89呪文、21段階の現在／最大MP9。

HP・職業・レベル・能力値・経験値・お金・所持品は変更しません。MP消費は別の全体設定「[MP消費なし](mp-support.md)」がOFFなら原作どおりです。最大MPは外伝1と同様に原作の計算結果へ介入します。全呪文の習得フラグが揃った人物のみ、最大MP計算の出力を9にします。

## 解析したアドレス

CPUアドレスと物理ROMオフセットは表中で区別しています。ROMヘッダーと人物読込・書込・呪文集計・検証値計算・複製の命令列を照合し、未確認の配置では有効化しません。ハッシュ判別、製品ROMの書換は使用しません。

| 用途 | 外伝2 | 外伝3 |
|---|---|---|
| 登録人物WRAM | D095 + 登録番号×80h | CBA1 + 登録番号×80h |
| 作業用人物 | D013 | CB1F |
| 通常セーブ人物（SRAMバンク0） | A018 + 登録番号×80h | A00A + 登録番号×80h |
| 人物の複製との差 | E5Eh | E52h |
| 人物検証値表（SRAMバンク0） | AE1C、BC7A | AE04、BC56 |
| 原作人物読込／保存 | 1175／11A3 | 1021／105A |

人物レコードは各128バイト、登録対象は20人です。外伝3では原作の21番目の特別作業領域を登録対象に含めません。

外伝2は習得フラグが+39h〜40h、現在MPが+41h〜4Ehです。魔術師系31呪文なので、先頭バイトの下位7ビットと残り7バイトを立てます。未使用の上位1ビットは保持します。

外伝3の魔術師・僧侶系は同じ位置ですが、魔術師系30呪文なので先頭は下位6ビットを立てます。錬金術師系は+6Ah〜6Dh、MPは+6Eh〜74hに別置きされます。27呪文の先頭は下位3ビットを立て、未使用ビットは保持します。外伝3のレコード末尾は外伝1・2の「Wizardry」識別文字列ではなく別の人物データなので、その領域へ識別文字列を書き込みません。

通常セーブと複製の人物レコード、両方の隣接2バイト加算の16ビット検証値を更新します。原作コピー処理の読込元から作業用人物を追跡し、選択人物なら呪文・MPだけ同期して未保存のHPなどを保持します。ステート復帰時は名前・識別部分とレコード全体の一致から再同期します。

## 検証

`spell_gaiden23_test` は各作品の登録人物すべてに実行し、全呪文のフラグ、現在MP、原作の最大MP計算、他人物・HPなどの保持、保存本体・複製・検証値、繰返し適用の同一性を確認します。SRAMを新しいコアへ渡して原作を通常起動し、モード選択を経ても習得・MPが残ることを検査します。

別の検証用コアでは原作の人物読込／保存を実行し、作業用人物の編集中に全呪文習得を行っても、その後の原作保存で習得・MPが失われず、未保存HPの変更が残ることを確認します。検証用入口コードは使い捨てコアだけに配置し、製品ROMには変更を加えません。

町のローカルステートでも同じ検証を行います。ROM・セーブ・ステートは配布物へ含めません。すべての呪文を画面から実際に唱える網羅テストではありません。

検証結果：外伝2・3の町と既存場面、外伝1・GBC版I〜IIIの回帰を含む26テストが成功。Windows Release、Android Debug（arm64-v8a／x86_64）のビルドが成功しました。Android実機での新機能の操作確認は未実施です。
