# GBC版Wizardry I：全呪文習得・現在MP／最大MP9

機能メニューのキャラクターサポートから対象の登録番号を選び、「全呪文習得」を実行します。Androidでは機能メニュー→サポート→キャラクターを選択です。全54呪文を習得し、魔術師系・僧侶系の7段階すべての現在MPと最大MPを9に設定します。通常の呪文使用による消費は残ります。

町の施設選択・酒場・宿屋などの施設内・迷宮・キャンプで実行できます。場所や入力待ち復帰先による制限はありません。戦闘とデータ転送中には実行しません。キャラクター名と登録番号で選択できます。名前は先頭から登録状態・文字数・最大8文字の形式で、原作の4種の文字選択表と濁点／半濁点変換表を照合してUnicodeへ復号します。外伝1の既存の習得処理・MPの挙動は変更していません。属性変更は外伝1とGBC I〜IIIで対応しています。[属性変更の解析・検証](wizardry1-alignment-analysis.md)を参照してください。

## ROM解析

ハッシュは使用せず、ROMヘッダーと以下の命令列・テーブルを照合します。

| 用途 | アドレス・形式 |
|---|---|
| 人物レコード取得 | 2776、C10A + 登録番号 × 6E（110バイト）、20人 |
| MP表示 | ROMバンク3 75BD：レコード+26h、上位4ビットが現在MP、下位4ビットが最大MP |
| MP領域 | C130～C13D（1人目）、魔術師7段階、僧侶7段階。9/9は99h |
| 習得フラグ取得 | ROMバンク3 7141～714A：レコード+34h+段階 |
| 習得領域 | C13E～C14B（1人目）、1段階1バイト、下位ビットから順番 |
| 段階別の開始番号 | ROMバンク2 6988：0,4,7,11,14,18,22,25,30,34,38,43,47,51,54 |
| 魔術師系の段階別数 | 4,3,4,3,4,4,3（計25） |
| 僧侶系の段階別数 | 5,4,4,5,4,4,3（計29） |
| 通常セーブ書込 | 2C03：C0F0からA011へ08B2バイト転送。人物はSRAMバンク0のA02Bから |
| セーブ検証値 | 2B30：A000～ABFDの8ビット加算。ABFEに合計、ABFFにその反転 |
| 通常セーブ読込 | 2C3C：人物データを復元し、上記検証値を原作処理で確認 |

習得マスクは `0F 07 0F 07 0F 0F 07 1F 0F 0F 1F 0F 0F 07`。未使用の上位ビットは保持します。WRAMと通常セーブの対象人物の名前領域が一致することを確認し、両方の呪文・MP領域のみ変更してセーブ検証値を再計算します。別人物、能力値、レベル、所持品、経験値、お金を変更しません。

場所を限定していたROMバンク2／3と入力待ち復帰先407C／4B15の判定を削除しました。モードCA11=3と戦闘用ROMバンク1、共通コピー0D49・クリア07D6・人物用の110バイト転送9か所を除外します。割込で中断された転送もスタックから検出します。

施設内の人物作業領域C9A2への読込元をコアの書込通知から追跡します。選択人物と対応する場合は、作業領域の呪文・MPも同時に更新し、未保存のHPなどは保持します。ステート読込後はレコード全体の一致から再同期し、同名人物などで対象を特定できない場合のみ対象人物への変更を拒否します。作成途中の未登録人物には適用しません。

## 検証

`spell_wizardry1_test` はローカルのROMとキャンプステートを使用します。全登録人物（fixtureは6人）について未習得フラグと使用途中のMPを用意し、54呪文のマスク、14バイトすべての現在／最大MP9、未使用ビットと他領域の保持、再実行の同一性、不正番号・空人物・保存側の別人物・戦闘・未確認ROMの拒否を確認します。

保存後のSRAMを別コアへ渡し、原作の読込ルーチン2C3Cを呼び出して、検証値の受理と人物レコードの復元一致も確認します。この検証用コアだけに入口コードを置き、製品側のROMは変更しません。ROM・セーブ・ステートは配布しません。

検証結果：町の施設選択・酒場メニュー・酒場の人物選択・宿屋の人物選択・宿屋の部屋選択でも同じ人物編集・原作セーブ再読込テストが成功。施設作業領域の同期、未保存HPの保持、他人物への非干渉、中断された転送の拒否も検査しました。外伝1の呪文・各場面・属性を含む関連9テストが成功。Windows ReleaseとAndroid Debugのarm64-v8a／x86_64ビルドが成功。Android実機での操作検証は未実施です。
