# ウィザードリィ・DQ3の戦闘報酬サポート

GB版ウィザードリィ外伝I〜IIIの経験値・お金と、GBC版Wizardry I〜III・GBC版DQ3の経験値・お金について、戦闘終了時の獲得倍率を
×1（通常）／×8／×16／×32／×64／×128／×256から選べます。初期値は×1です。

Androidは機能メニュー→「サポート」、Windowsは機能メニュー末尾の
「獲得経験値」「獲得お金」で左右を操作します。Aで倍率を変更しません。
Androidの項目は左半分／右半分へのタップでも変更できます。
設定は保存され、ROMを開き直した後とリセット後にも適用します。
ステート読込は現在の倍率設定を維持し、ステート側の倍率へは変更しません。

## 適用範囲

原作が計算した1人分の配分額に倍率を掛け、原作の表示・加算・保存処理へ戻します。
配分対象の判定と割り算の切り捨ては原作に従います。例として原作で経験値290を得る場合、×8では2,320です。
総額へ倍率を掛けてから人数で割る方式とは、切り捨て分だけ異なる場合があります。
既に配分済みの報酬や所持残高全体を増やす機能ではありません。
経験値を変えるとメッセージの長さ・経過フレームも変わるため、後続のランダムなお金の基礎額が変わる場合があります。

ROMヘッダーと報酬処理・数値格納処理の命令列で対応版を確認します。ハッシュは使用しません。
未確認の版と対応表にない作品には倍率を適用しません。
ROMを書き換えず、Gambatteの書き込みコールバックで配分額や獲得分の加算結果を調整します。
外伝は32ビット上限、GBC版I〜IIIは6バイトBCDの12桁上限で止め、桁あふれによる減少を防ぎます。

## 実装位置

ROMバンク4の経験値配分は6AA9、金額配分は6BCAから共通の4バイト格納処理0308を呼びます。
最後のバイトを書いたときのPC=0310、復帰先6AAF／6BD3、作業RAM D068／D0C0と
保存バンクD0AE=4をすべて確認して適用します。表示・各キャラクターへの加算は、その後の原作処理が行います。
音声転送と同じコールバック内で処理するため、倍速音声のコールバックを置き換えません。

## 検証

`reward_test`はローカルの戦闘勝利直前ステートから実際の戦闘を終了させ、
経験値とお金の全7倍率をそれぞれ独立に検証します。
対象戦闘では経験値の基礎額290、通常時のお金の基礎額18でした。
原作の配分対象3人への加算、対象外メンバーの非加算、他のキャラクター項目の維持、
×1で原作コアの戦闘状態と完全一致、未確認命令列の拒否、32ビット上限を確認しています。

```powershell
.\build\Release\reward_test.exe .rom/wizardrygaiden1.gb build/rewards/before-win/core.bin
```

この環境の勝利直前ステートは、コピーした通常セーブと既存の検証用操作手順から作ったものです。
ROM・セーブ・ステートは配布物に含めません。
CTestへ登録する場合はCMakeの`GBWIZ_REWARD_CHECKPOINT`にローカルのステートパスを指定します。

Androidの`CoreTest.testGaiden1Rewards`も同じステートで全倍率の実加算とリセット後の設定保持を検証します。
fixtureはアプリcache内の`test.gb`と`gaiden1-before-win.bin`です。
`RewardViewTest`は通常の保存先や設定を変更せず、縦・横画面のサポートメニューを描画します。
2026-10-29にWindowsの14テストとPixel 9aの3テスト（報酬、DQ3歩行回帰、メニュー描画）が成功しました。
実機で描画した縦・横のサポート画面も画像で確認しています。

他作品への展開、全状態異常・人数・高レベルを組み合わせた網羅検証は今後の作業です。

## 外伝IIの経験値倍率

外伝IIでは経験値・お金をそれぞれ×1／×8／×16／×32／×64／×128／×256から選べます。

経験値・お金の倍率設定は外伝I・IIで共通です。リセット後も両方を維持します。外伝IIIも経験値・お金の両倍率に対応しています。

外伝IIではPC=0323、書込先CF77、CFBD=4、復帰先6AFCを確認し、原作の1人分の配分額CF74〜CF77だけを倍率化します。[解析記録](gaiden2-experience-analysis.md)も参照してください。

`reward_gaiden2_test`で全7倍率×全5速度を、実際の勝利直前ステートから検証しました。1人125の経験値が×8で1,000、×256で32,000となり、6人分の登録データとSRAMが一致します。×1の原作コア状態との一致、対象外状態の非加算、経験値・お金以外のキャラクター項目の保持、呼出元・バンクの検査、32ビット上限、お金倍率の拒否、ステート復帰後の設定保持も確認しています。

既存を含むWindows CTest 30件が成功しました。Android Debugのarm64-v8a / x86_64をビルド済みです。Android用には `CoreTest.testGaiden2ExperienceRewards` を追加し、全倍率・SRAM反映・リセット後の設定保持を検査しますが、今回の実機テストは未実施です。必要なfixtureは `gaiden2.gb` と `gaiden2-before-experience.bin` です。

CTestのローカル検証用ステートは `GBWIZ_GAIDEN2_REWARD_CHECKPOINT` で指定します。ROM・ステートは配布物に含めません。

## 外伝IIIの経験値倍率

外伝IIIも×1／×8／×16／×32／×64／×128／×256に対応しました。お金倍率も独立して変更できます。操作・設定保存・リセット・ステート復帰時の倍率維持は外伝IIと同じです。

外伝IIIの原作配分はバンク4 6F83〜6F88から029Eの4バイト格納を呼びます。PC=02A6、書込先CA78、CAC7=4、復帰先6F89を確認して、分配後の1人分CA75〜CA78を倍率化します。表示用のCAD9へのコピー、状態値3未満への加算（CB4C）、原作の保存105Aへ戻します。キャラクター作業領域はCB1F、登録レコードはCBA1、SRAMの登録先頭はバンク0のA00Aです。

検証用には、コピーした迷宮ステートから原作の通常エンカウント処理0F62を呼び出し、通常の戦闘・勝利処理で獲得した経験値配分の直前を保存しました。ROMファイルや個人の通常セーブは変更していません。この戦闘の配分額は6人それぞれ80で、×8で640、×256で20,480となり、原作の登録レコードとSRAMに反映されます。

共通の報酬テストで外伝IIIの全7倍率×全5速度、×1の原作一致、対象外状態の非加算、他のキャラクターフィールドの保持、ステート復帰後の設定維持、誤った呼出元・バンクの拒否と32ビット上限を確認しました。検証用ステートはCMakeの `GBWIZ_GAIDEN3_REWARD_CHECKPOINT` で指定します。

Androidの `CoreTest.testGaiden3ExperienceRewards` は `gaiden3.gb` と `gaiden3-before-experience.bin` を使い、全倍率のSRAM反映とリセット後の設定保持を検査します。今回の実機実行は未実施です。

助っ人枠を含む全メンバー構成、全状態異常、逃走終了などの網羅検証は行っていません。配分資格と保存対象の判断は原作に従います。

外伝III追加後、既存機能を含むWindows CTest 31件が成功しました。Windows本体、Android本体（arm64-v8a / x86_64）、AndroidテストAPKのビルドも成功しています。

## 外伝IIのお金倍率

機能メニューの「獲得お金」を左右で変更します。経験値倍率とは別に設定でき、Androidでは行の左右タップでも変更できます。[解析・検証の詳細](gaiden2-gold-analysis.md)を参照してください。

PC=0323、書込先CFD2、CFBD=4、復帰先6C1Fを照合し、原作で人数分配済みのお金CFCF〜CFD2だけを倍率化します。表示・状態判定・各人への加算・保存は原作の処理を使用します。

お金の全7倍率×全5速度を、経験値×1・×256それぞれと併用して検証しました。正常な6人への実加算とSRAM保存、他の登録人物・全所持金以外項目の保持、対象外状態、所持金の上限、誤った呼出元の拒否、ステート復帰後の設定保持を確認しています。

外伝IIのお金倍率追加後、既存を含むWindows CTest 32件が成功しました。Windows本体・Android本体（arm64-v8a / x86_64）・AndroidテストAPKのビルドも成功しています。

## 外伝IIIのお金倍率

「獲得お金」を左右で変更し、経験値倍率と併用できます。[解析と検証](gaiden3-gold-analysis.md)を参照してください。

PC=02A6、書込先CADC、CAC7=4、復帰先70ACを照合し、原作が分配した1人分のお金CAD9〜CADCを倍率化します。全7倍率×全5速度を経験値×1／×256それぞれと併用して確認し、実加算・SRAM保存・配分資格・所持金上限・他項目保持の検証が通っています。

外伝IIIのお金倍率追加後、既存を含むWindows CTest 33件が成功しました。Windows本体・Android本体（arm64-v8a / x86_64）・AndroidテストAPKもビルド済みです。

## GBC版Wizardry Iの経験値倍率

経験値の全7倍率に対応しました。通常の1人分156の戦闘で、×8なら1,248、×256なら39,936を加算します。6バイトBCDの原作処理へ接続し、各人物への加算とSRAM反映を検証しています。操作と設定保存は外伝と共通です。詳細は[解析記録](wizardry1-experience-analysis.md)を参照してください。

## GBC版Wizardry Iのお金倍率

お金の全7倍率にも対応しました。原作の抽選・人数分配後の金額を倍率化し、6バイトBCDの加算・表示・通常セーブへ渡します。経験値倍率と併用できます。詳細は[解析記録](wizardry1-gold-analysis.md)を参照してください。

## GBC版Wizardry IIの経験値・お金倍率

IIも経験値とお金の全7倍率に対応しました。各倍率を独立して設定し、併用できます。原作の6バイトBCD形式の人数配分後に倍率を適用します。全倍率・全速度、非参加人物の非加算、実加算と通常セーブ、原作の配分条件と12桁上限を確認しています。[解析記録](wizardry2-rewards-analysis.md)。

## GBC版Wizardry IIIの経験値・お金倍率

IIIも経験値・お金の全7倍率に対応しました。両倍率を独立して設定・併用できます。これで外伝I〜IIIとGBC版I〜IIIの6作品すべてで両倍率に対応しています。IIIの全倍率・全速度、SRAM反映、原作の配分対象と12桁上限を確認しています。[解析記録](wizardry3-rewards-analysis.md)。

## GBC版DQ3

経験値は人数配分後の1人分を倍率化し、お金は今回獲得した金額だけを倍率化します。経験値は原作の職業別上限、所持金は999,999で止めます。商人の追加獲得分にも同じお金倍率を適用します。詳細は[解析と検証](dq3-rewards-analysis.md)を参照してください。
