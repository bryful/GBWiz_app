# DQ3 基本戦闘の検証（2026-10-29）

ROMや通常セーブを書き換えず、新規冒険の操作から作成したローカルのステートで検証しています。
ROM・ステートは配布物に含めません。

## 再実行

リポジトリ直下から、ローカルに残っているフィールド到達時のステートを使用します。
`build/dq3/out4/core.bin`がない環境では、開始イベントと王への謁見を終え、アリアハンから
南のフィールドへ移動したステートを用意する必要があります。この経路はそのステート専用です。

```powershell
foreach ($speed in 3,4,6,8) {
    .\build\Release\play_probe.exe .rom/DQ3.gbc build/dq3/absent.sav tests/scripts/dq3-field-battle.txt "build/dq3/full-$speed" $speed build/dq3/out4/core.bin
}
```

倍率引数は実速度の2倍です。出力の`forwarded.csv`で、曲番号73→26→41→4、
効果音カウンターの増加を確認しました。各ステップのBMPで戦闘・勝利・フィールド復帰を確認しています。
2倍速の詳細画面は`build/dq3/battle-logged/4.bmp`（攻撃）、`10.bmp`（勝利）、
`18.bmp`（メダル）、`20.bmp`（フィールド）にも残っています。

`play_probe`の出力ステートはゲーム用コアだけです。途中の戦闘ステートから再開すると、
その時点のBGMは次の曲指示まで音声用コアへ復元されません。
そのため、曲の転送確認はフィールドから戦闘終了までを連続実行した`full-*`の記録を使います。
アプリ本体の複合ステートは映像・音声とも保存し、別途`turbo_state_dq3`で検証しています。

WindowsのCTestは13件すべて成功しました。タイトル曲の先頭7音は音程が一致し、
各発音間隔の差は最大3フレームです。

## Android実機でのコア検証

Pixel 9aの`CoreTest.testDq3FieldBattle`で、同じステートと操作スクリプトを全4倍率で実行しました。
最初の検証では各操作後の42画面×4倍率＝168画面がWindows版のBMPと全画素で一致しました。
スクロール修正後は遭遇タイミングが変わるため操作を58ステップ（3,904フレーム）へ延長し、期待画面を再生成しました。
修正後も58画面×4倍率＝232画面がWindows版と一致し、全倍率で勝利曲からフィールド曲への復帰を確認しました。
音声に非ゼロのサンプルがあり、各倍率で出力サンプル数が1倍速の範囲に保たれることも確認しました。
歩行・戦闘・音声クロックのAndroid実機テスト3件が成功しています。
これはJNI経由のコア検証であり、画面上のタッチ操作やAudioTrack・実機スピーカーの確認は含みません。

必要なローカルfixtureはアプリのcache内の`dq3.gbc`、`dq3-field.bin`（上記ステート）、
`dq3-field-battle.txt`、`dq3-expected/<倍率引数>/<1〜58>.bmp`です。
期待画面は上記Windowsコマンドの`full-*`からコピーします。テストAPK・アプリには同梱しません。

## 通常速度との音程・発音時刻の比較

通常速度の操作記録は`build/dq3/native-long/commands.csv`に残っています。
`play_probe`の`trace`モードで、`build/dq3/native-long.txt`を同じフィールドステートから実行しました。
このスクリプトは初回の42ステップ版の末尾へA／WAITを4回、その後B 8／WAIT 600を追加したものです。

```powershell
.\build\Release\play_probe.exe .rom/DQ3.gbc build/dq3/absent.sav build/dq3/native-long.txt build/dq3/native-long trace build/dq3/out4/core.bin
.\build\Release\music_probe.exe .rom/DQ3.gbc build/dq3/native-long/commands.csv
```

戦闘曲26は切替直後の2回、勝利曲41は1回の再発音を除く25音で、音程と発音時刻が一致しました
（起動時刻の差を補正し、時刻差±2フレーム以内）。比較対象はパルス1チャンネルのNR13／NR14です。
曲切替時の再発音や全チャンネル波形の一致を保証する比較ではありません。

フィールド曲4は厳密比較が不一致です。通常速度では周波数下位値114、音声用コアでは115／117など、
細かな値の差を確認しました。原因は未特定です。ユーザーの実機確認で音楽は特に問題なしとの結果のため、この差の調査は優先度を下げています。
上記コマンドはこの不一致をFAILとして表示し、終了コード1を返します。
戦闘曲と勝利曲のPASSだけを根拠に、全曲が完全一致したとは扱いません。
全呪文・全効果音・長時間プレイは引き続き未検証です。

## 倍速スクロールの停止対策

ユーザーから倍速時のスクロールがガタつくとの報告があり、方向キーのリピート補正が
移動中もキーを離していることを再現しました。2倍速では本来4ピクセルずつ進む区間で、
最初の一歩後に8表示フレーム連続でスクロール位置が固定されていました。
スクロールを検出している間は保持中の方向キーを連続して渡し、メニュー等では通常の補正へ戻すよう修正しました。

`dq_turbo_test ROM build/dq3/east/core.bin`で、全4倍率において32表示フレーム左へ移動し、
その後58フレーム方向キーを離した映像を、元ゲームの連続入力と各フレームで比較します。
旧処理では失敗し、修正後は成功しました。
Androidの`testDq3HeldScroll`も同じ検証を行い、Pixel 9aで成功しています。
Android用fixtureは町での歩行ステート`dq3-walk.bin`（`build/dq3/east/core.bin`）です。
修正後の見た目は実機で再確認します。
